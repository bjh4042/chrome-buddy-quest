## 브라우저에서 직접 확인한 흐름

클라우드 Chrome 데스크톱에서 다음을 실제 버튼과 입력으로 확인했습니다.

1. 시작 화면 → 자유 연습 → 시작 메뉴 → Excel 실행.
2. A1에 100 확정, A2에 `=A1*2` 확정 → A2가 **200**으로 표시됨.
3. Excel 최소화 → 작업 표시줄 복원 → 값 200과 창 크기 유지.
4. 시작 메뉴 → 설정 → 최대화 → 개인 설정 → 보라 오로라 선택 → 바탕화면의 실제 CSS 배경 변경 확인.
5. 작업 표시줄의 빠른 설정 열기, Wi-Fi·밝기·볼륨 컨트롤 표시 확인.

한글·PowerPoint·Edge·탐색기의 상세 흐름은 컴포넌트 회귀 테스트로 검증했습니다. 이 기록은 해당 프로그램의 전체 브라우저 실기, 실제 Windows PC·Edge·iPad·갤럭시탭 실기 검증을 대신하지 않습니다.

## 남아 있는 범위와 운영 전 확인

- 실제 Windows 11 26H2 장치와 픽셀 단위 비교, 전체 메뉴·전체 OS 기능 검수는 수행하지 않음.
- 한글/Excel/PowerPoint 전체 기능 및 HWP/HWPX/XLSX/PPTX 완전 호환은 미지원. 탐험대 JSON/CSV/TXT 형식을 정확히 표시함.
- Wi-Fi·Bluetooth·볼륨·전원·업데이트는 학습 상태. 실제 기기를 변경하지 않음.
- Edge의 사이트와 검색 결과는 로컬 학습 자료. 실제 인터넷 전체와 연결한 브라우저가 아님.
- 학교 PC의 설치 글꼴과 화면 배율은 서로 다름. 실제 수업 기기에서 한글 입력, 문서 선택, 그림 크기, 파일 다운로드, 소리/네트워크 안내를 확인해야 함.
- 로그인/서버/학생별 계정이 없으므로 동일 브라우저의 기록은 공유됨. 문서별 다운로드가 백업 수단.
- 728KB 내외의 단일 JS 번들 경고와 caniuse 데이터 갱신 안내가 있음. 빌드 실패는 아니며 느린 학교 네트워크에서는 첫 로딩 시간을 확인할 것.

## 원본에서 발견해 고친 대표 오류

- `naver.com.evil.example`도 네이버 방문으로 판정하던 정규식.
- 클릭 안내와 별 3개 요구 불일치.
- 서로 다른 바탕화면 아이콘을 빠르게 클릭해도 실행되는 동작.
- 시작 메뉴·탐색기·리본의 무동작 버튼.
- 다른 Wi-Fi도 동일 비밀번호로 성공하던 판정.
- 볼륨 48~52를 모두 50으로 인정하던 판정.
- 창을 끌어 화면 밖으로 잃거나 최소화 중 크기가 작아지는 문제.
- 선택 영역을 유지하지 못한 서식 변경과 저장 없이 성공하던 동작.
- 8초 후 학생 의사와 관계없이 다음 단계로 넘어가던 흐름.
