# 윈도우 탐험대 v1.1 — 작은 화면 팝업 수정

2026-11-02. 낮은 해상도에서 확인·열기·저장·취소 버튼이 잘리는 문제를 수정하고, Edge 신규 실습 8개를 포함해 **49개 미션**으로 확장했습니다.

## 적용한 구조

- 팝업을 프로그램 창 밖의 화면 기준 영역에 표시합니다. 프로그램 창을 줄이거나 스크롤해도 팝업이 잘리지 않습니다.
- 제목과 하단 작업 버튼은 별도 고정 영역입니다. 긴 목록·양식·설명만 가운데에서 스크롤합니다.
- 표시 가능한 화면의 실제 폭·높이·위치를 반영합니다. `visualViewport`의 resize/scroll과 브라우저 창 크기 변경을 처리합니다.
- 좁은 화면에서 그림 목록은 2열, 큰 화면은 3열입니다. 썸네일 크기를 제한하고 파일명과 열기/취소를 하단에 함께 둡니다.
- 긴 파일명은 줄바꿈하고 입력란은 화면 폭 안에 둡니다. Tab·Shift+Tab·Esc와 팝업 종료 후 포커스 복원을 지원합니다.
- 화면을 줄이면 프로그램 창의 크기와 위치도 화면 안으로 보정합니다. 짧은 화면에서는 안내 영역을 줄이고 리본과 내용에 스크롤을 제공합니다.
- 바탕화면 아이콘 때문에 작업 영역이 넘쳐 창 제목줄까지 밀리던 문제를 수정했습니다. 아이콘은 다음 열로 정렬하며 안내 손가락 위치도 실제 아이콘 위치를 따라갑니다.

## 적용 대상

그림 선택, 표 만들기, 한글 저장/불러오기·이모지, 탐색기 생성/이름 변경/이동/삭제/문서 편집, PIN/암호·Wi-Fi·Bluetooth·잠금 테스트, 새 발표 확인, 용어 사전과 학습 기록 초기화. Edge의 즐겨찾기·다운로드 목록·다운로드 설정·저장 폴더 선택도 같은 화면 기준 팝업을 사용합니다.

PowerPoint 슬라이드 쇼는 제목/종료 영역과 이전·다음 버튼을 분리하고 남은 공간에 16:9 슬라이드를 맞춥니다. 작은 설정 창의 범주 아이콘에는 접근성 이름을 부여하고, 탐색기 좁은 창에서는 파일 이름을 우선 표시합니다.

## 실제 브라우저 배치 확인

Chrome의 독립 iframe 뷰포트에서 앱을 실행했습니다. 아래 수치는 CSS 픽셀 기준이며 실제 물리 기기별 실행이나 OS 화면 배율 테스트를 의미하지 않습니다. 크기 변경 이벤트가 적용된 뒤 실제 DOM 사각형을 읽어 확인했습니다.

| 앱 뷰포트 | 그림 선택창 전체가 화면 안에 있음 | 열기·취소 버튼이 화면 안에 있음 | 본문 스크롤 |
|---|---|---|---|
| 1024×600 | 통과 | 통과 | 내용이 들어갈 때는 불필요 |
| 800×600 | 통과 | 통과 | 내용이 들어갈 때는 불필요 |
| 640×480 | 통과 | 통과 | 내용이 들어갈 때는 불필요 |
| 360×640 | 통과 | 통과 | 내용이 들어갈 때는 불필요 |
| 568×320 | 통과 | 통과 | 사용 가능 |
| 320×360 | 통과 | 통과 | 사용 가능 |

320×360에서 직접 수행한 흐름:

1. 한글 그림 선택 → 꽃다발 선택 → 열기 → 그림이 문서에 삽입됨.
2. 저장 → 파일 이름 입력 → 하단 저장 → 불러오기 → 저장한 이름을 선택 → 해당 문서 복원.
3. 표 만들기 → 만들기/취소 버튼의 화면 경계 확인 → 취소.
4. 탐색기의 새 폴더 양식 → 확인/취소 버튼의 화면 경계 확인 → 취소.
5. 설정 → PIN 만들기 → 확인 입력과 하단 확인 → 잠금 테스트 → 하단 로그인으로 해제.
6. 작은 설정 창의 이름 없는 범주 아이콘을 발견해 접근성 이름과 툴팁을 추가함.
7. 바탕화면 최소 높이 때문에 앱 제목줄이 위로 밀리는 현상을 발견해 실제 창 전체가 화면 안에 남는 것을 재확인함.

568×320에서는 PowerPoint 슬라이드 쇼의 종료·이전·다음 버튼이 화면 안에 남는 것을 확인했습니다.

Edge 추가 브라우저 확인:

- 이름과 폴더를 지정한 즐겨찾기 저장 → 목록에서 학교 사이트 다시 열기.
- TXT 연습 파일 다운로드 → 폴더에 표시 → 탐색기에서 해당 파일이 선택됨 → 문서로 이동 → Edge 목록의 경로가 `내 PC / 문서`로 갱신됨.
- 기본 저장 위치를 문서로 바꾼 후 다음 다운로드가 문서에 저장되며, 같은 이름은 `(1)`, `(2)`로 구분됨.
- `안전` 검색으로 실제 본문의 일치 항목 4개가 강조되고 다음 항목으로 이동함. 학교 사이트 탭을 닫은 뒤 메뉴에서 다시 열기 성공.
- 320×360에서 즐겨찾기 완료/취소, 파일 이동/취소, 저장 폴더 선택/취소가 모두 화면 안에 남음.
- 짧은 Edge 창에서 도구 모음 때문에 본문 높이가 0이 되던 문제를 수정함. 최종 검수에서 내부 높이 207.5px 중 본문 64.375px, 도구 모음 114.125px를 확보하고 도구 모음도 내부 스크롤 가능함. 같은 작은 창에서 다운로드 버튼 클릭 → 다운로드 팝업 표시까지 다시 확인함.

실제 PC의 TXT 저장 완료 여부는 브라우저 다운로드 이벤트로 확인하지 못했으므로, 브라우저 실기 확인은 앱 연습 파일 저장·경로와 TXT 내보내기 요청까지를 뜻합니다. 네이티브 다운로드 요청의 파일명·내용은 자동 테스트로 별도 검증했습니다.

## 자동 검증

현재 전체 **24개 파일·165개 테스트 통과**, TypeScript 검사 통과입니다. 정적 배포 빌드는 배포 시 최종 소스에서 생성합니다.

추가 검증에는 팝업 포털과 스크롤 영역/하단 영역 분리, 6개 뷰포트 크기, 키보드 표시로 줄어든 가시 영역의 위치/높이 갱신, 중첩 팝업·포커스, 화면 밖으로 나가지 않는 메뉴·창 크기 계산, 실제 저장·사진 삽입 동작이 포함됩니다.

Edge 확장 회귀 검증에는 즐겨찾기 저장·다시 열기, 다운로드 파일과 출처·저장 폴더, 앱 파일 탐색기로 위치 표시, 문서로 이동한 파일의 위치 갱신, 기본 폴더 변경·파일별 위치 선택, 페이지 찾기·닫은 탭 복원과 잘못된 완료 판정 차단이 포함됩니다. 기존 41개 미션 기록을 유지하면서 첫 신규 임무부터 재개하는 것도 확인했습니다.

다운로드 경로는 앱 안의 연습 폴더를 뜻합니다. 실제 브라우저에 요청한 TXT 내보내기는 해당 브라우저의 다운로드 설정을 따르며, 앱의 위치 변경으로 기존 파일이나 실제 PC의 전역 경로가 바뀌지 않습니다. 절차는 [Edge 실습 안내](EDGE_PRACTICE_v1_1.md)를 참고하세요.

화면 키보드의 이벤트 처리는 자동 회귀 테스트로 검증했습니다. 실제 iPad·갤럭시탭 키보드와 브라우저 확대 배율별 실기 테스트는 수행하지 않았습니다.
